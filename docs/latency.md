# 지연 측정 (기능명세 12장)

로컬 루프백에서 잰 값이다. **실제 네트워크·저사양 기기·발표장 Wi-Fi의 값이 아니다.**
화면·서버가 같은 PC에서 돌고, 응답은 규칙 기반(LLM 없음)이라 서버 시간이 짧다.

두 실행의 차이(예: `/api/react` 중앙값 21.6 → 31.7 ms)는 같은 PC의 다른 부하 때문일 수 있고, 통합으로 달라졌다고 단정할 근거는 없다.

- 입력→로컬 반응은 서버와 무관한 값이다(`/api/react`는 전송할 때만 호출).
- 전송→의미 표정은 `/api/react`와 `/api/conditions/parse`가 **둘 다** 끝난 뒤 표정이 정해지기 때문에 두 응답 중 느린 쪽에 가깝다.
- 표정이 바뀌는 시각은 DOM 속성이 바뀐 시각이다. 화면에 실제로 그려지는 프레임과 모션의 완료 시각은 포함하지 않는다.

## 오래된 응답 무시

아래 표의 10/10·3/3은 이번 실행(D6)에서도 같았다(스크립트 요약: 오래된 응답 무시 10/10, 표정 서버 지연 복구 3/3). 이전 실행(D5)도 같은 값.

`/api/react`·`/api/conditions/parse`의 **첫 요청만 1,000 ms 지연**시켜 응답이 뒤집혀 도착하게 한 뒤
A(“월세 60 이하로, 40분 안쪽”) → 80 ms 뒤 B(“고마워”)를 보낸다.

| 검사 | 기대 | 결과 |
|---|---|---|
| 응답이 역순(B가 먼저, A가 나중) 도착 | 매 회 | 10/10 |
| A의 늦은 응답 뒤에도 표정이 A(`listening`)가 아님, B(`happy`) 또는 복귀 상태 | 매 회 | 10/10 |
| A의 조건 후보 카드(“조건 확인”)가 나타나지 않음 | 매 회 | 10/10 |

표정 서버가 **시간 제한(1.5초)을 넘게** 늦으면(2.2초 지연 주입) 조건 카드는 정상 표시되고 표정은 `neutral`로 복구: 3/3.

한 번 더: 지연을 2초로 줬을 때는 1.5초 제한에 먼저 걸려 A의 응답이 아예 도착하지 않는다(그 경우는 역순 도착이 아니라 시간 초과 복구 경로).
그래서 역순 검사는 제한 안쪽인 1초 지연을 쓴다.

## 같은 코드로 한 번 더 돌린 앞선 실행(참고, D5 안)

통합 전 같은 스크립트를 몇 분 앞서 실행했을 때는 중앙값이 더 컸다.
전송→의미 표정 중앙값 109.2 / p90 174.8 / 최대 252.3, `/api/react` p90 97, `/api/compare` 중앙값 56.9.
오류 0/30, 역순 응답 10/10은 같았다. 다른 작업자들이 같은 PC에서 서버·빌드를 돌리고 있어 값이 흔들린다.
**한 번의 값을 합격선으로 쓰지 말고 범위로 읽는다.**

## 한계

- 로컬 루프백이라 네트워크 지연이 없다. 발표장·모바일 회선에서는 `/api/*` 시간이 이 값에 더해진다.
- 규칙 기반 어댑터의 값이다. 모델(LLM) 의미 판단으로 바꾸면 전송→의미 표정이 크게 늘 수 있다. 그때는 다시 잰다.
- 표본이 30회이고 p90은 상위 3번째 값이다. 꼬리 지연(p99)은 판단하지 못한다.
- 지연 주입은 브라우저 요청 가로채기로 시뮬레이션한 것이다. 실제 서버 장애·패킷 손실과는 다르다.
- 헤드리스 브라우저 한 종류, 창 크기 한 가지. 저사양 기기 시험은 하지 않았다.

## 다시 재는 방법 (Windows PowerShell)

서버 두 개를 띄운 뒤(예: [발표 시나리오](demo-script.md)의 명령) 다른 터미널에서:

```powershell
cd frontend
node scripts/measure-latency.mjs --base http://127.0.0.1:5194 --n 30 --out ../.playwright-mcp/d5-qa  # 이번(D6) 실행은 5196·d6-polish/latency
```

옵션: `--n`(반복, 기본 30), `--stale`(역순 응답 반복, 기본 min(n,10)), `--skin renti`(렌티 스킨), `--playwright <playwright-core 폴더>`.
종료 코드 0 = 오류 0·역순 응답 전부 통과·시간 초과 복구 전부 통과. 서버는 이 스크립트가 띄우거나 끄지 않는다.

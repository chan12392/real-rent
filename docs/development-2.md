# 개발 2 작업 안내

담당 범위: 서버·DB, 주소·교통 API, 캐시·오류 처리, 배포.
현재 실행되는 기능은 `GET /api/health`뿐이다. DB·외부 API 제공자와 배포 환경은 아직 선택하지 않았다.
공통 리팩터링 이후 준비된 개발 2 브랜치에서 아래 순서대로 작은 PR을 만든다.

## 수정할 위치

| 위치 | 맡을 작업 |
| --- | --- |
| `backend/app/main.py` | FastAPI 조립, 라우터·미들웨어 등록 |
| `backend/app/core/config.py` | 환경 변수와 서버 공통 설정 |
| `backend/app/api/` | 화면이 호출할 HTTP API, 입력 검증과 오류 응답 |
| `backend/app/schemas/` | 팀이 합의한 공통 요청·응답 형식 |
| `backend/app/db/` | DB 스키마, 저장·조회, 마이그레이션 |
| `backend/app/integrations/` | 주소·교통 API 클라이언트, 캐시, 제공자 오류 처리 |
| `backend/.env.example` | 실제 값 없이 필요한 설정 이름 공유 |
| `deploy/` | 선택한 환경의 배포 설정과 실행·복구 안내 |
| `backend/tests/` | 서버·DB·외부 API 동작 검사 |

개발 3의 코드는 `app/engine/`, 분석의 계산·필터·정렬 함수는 `app/domain/`에 있다.
현재는 두 영역의 안내만 존재한다. 개발 2는 합의한 함수의 입력·출력을 API에 연결한다.

## 착수 순서와 완료 기준

1. **연결 규약**: 개발 1·3·분석과 조건, 주소 후보, 경로, 비교 결과의 예시를
   `docs/api.md`에 정한다. 성공·실패·미확인 값의 표현까지 맞추고 모델과 테스트를 추가한다.
2. **서버·DB**: 저장할 대상과 DB를 선택한다. 저장·조회와 마이그레이션을 구현하고
   서버를 다시 시작해도 데이터가 유지되는지 확인한다.
3. **주소·교통 API**: 제공자를 정하고 `app/integrations/`에서 호출한다.
   시간 초과, 호출 제한, 제공자 오류, 응답 누락을 검사한다. 키는 서버에만 둔다.
4. **캐시·오류 처리**: 조회 조건을 포함한 키와 유효 기간을 정한다.
   동일 조건 재사용, 조건 변경 시 별도 조회, 만료와 실패 후 처리를 검사한다.
   조회 실패나 미확인 시간을 0원·0분으로 바꾸지 않는다.
5. **화면·AI·계산 연결**: 화면 입력에서 주소 확인·비교까지 흐름을 연결한다.
   경로 응답 정리는 개발 3, 비용 계산·필터·정렬은 분석의 함수를 사용한다.
6. **배포**: `deploy/README.md`에 실제 환경과 명령을 기록한다.
   배포 주소에서 화면 → API 연결, 저장 데이터, 외부 호출과 오류 표시를 확인한다.

아직 선택하지 않은 DB·호스팅·캐시 제품이나 LLM 의존성을 준비 작업에서 미리 설치하지 않는다.

## 첫 실행

PowerShell에서 **개발 2 작업 폴더**를 연 뒤:

```powershell
cd backend
uv sync --frozen
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
uv run uvicorn app.main:app --reload --host 127.0.0.1 --port 8000 --env-file .env
```

`http://127.0.0.1:8000/docs`에서 실제 API를 확인한다.
화면 연결은 루트 README의 프론트엔드 실행 절차를 따른다.

```powershell
uv run ruff check app tests
uv run python -m pytest
```

PR에는 사용한 합성 입력·통과한 검사·미확인 외부 연결을 기록한다.
분석 담당자에게 검증 결과를 전달하고, 다른 팀원의 리뷰와 별도 병합 지시를 기다린다.

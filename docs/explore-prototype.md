# 대화·지도·캐릭터 웹 시제품

작업 브랜치: work/yunsoo. 합성 데이터 시제품이며 공개 배포는 아직 수행하지 않았다.

## 합의한 경험

흰색 배경·초록색 강조, 기본 글자 #333333. 데스크톱 대화창은 420px 고정, 나머지 공간은 지도에 사용한다. 큰 캐릭터 옆 말풍선.
집 선택 후 상세 패널은 360px 너비로 지도 오른쪽에 겹쳐 열리고 지도를 밀지 않는다.
좁은 데스크톱(1050px 이하)은 두 패널을 320px로 줄인다. 지도는 Leaflet + OpenStreetMap 거리 타일을 사용한다. 집 위치는 동네 대표 지점이고 실제 매물 주소가 아니다.
추천 매물은 연노랑 맵핀 안의 흰 원에 캐릭터 얼굴을 표시하고, 나머지는 작은 초록 맵핀을 사용한다.
모든 집은 선택 가능하며 선택한 집을 유지한 채 조건 수정 시 판정·표정·이유를 갱신한다.
캐릭터는 사용자가 선택한 우사기 표정 시트를 투명 배경 아틀라스로 정리한 PNG를 사용한다.
6가지 표정은 기존 얼굴을 짧게 내린 뒤 새 얼굴이 나타나는 전환을 사용해 이중 얼굴 겹침을 줄인다.
표정 전환 반응과 함께 대화창의 큰 캐릭터는 표정에 맞는 바운스·갸웃 등 연속 CSS 동작을 실행한다.
450ms 미만의 짧은 검색 상태는 표시하지 않아 표정 깜빡임을 줄인다. 이미지 전체 CSS 동작이다.
눈·귀·팔을 독립적으로 움직이는 리깅/프레임 애니메이션은 아직 아니다. 움직임 줄이기 OS 설정을 따른다.

대화는 친근한 존댓말, 규칙 기반 추출·모호한 표현 재질문. 필수/선호는 카드와
‘꼭/가능하면’ 표현으로 변경한다. 첫 기본값을 확인하는 버튼을 제공한다.
월 지출은 월세+관리비+통근비. 출근 기본 20일. 환승 기본 제한 없음.
API 규약·미확인 우선순위·지원 표현은 docs/api.md를 따른다.
화면을 사용한 뒤 상세 패널 정보량을 사용자와 재검토한다.

## 팀원 브랜치 체험

main 병합 없이 `work/yunsoo` 브랜치만 받아 실행한다. 작업 중인 변경이 있다면 먼저 커밋하거나 별도로 보관한다.

```sh
git fetch origin
git switch --track origin/work/yunsoo
npm run setup
npm run dev
```

이미 해당 로컬 브랜치가 있다면 `git switch work/yunsoo` 후 `git pull --ff-only origin work/yunsoo`를 사용한다. Node.js 24.14 이상 25 미만, uv 및 Python 3.12 이상이 필요하다. 실행 후 http://127.0.0.1:5173 에 접속한다. GitHub 브랜치 링크는 코드 공유용이며 공개 웹 배포 주소는 아니다.

## 실행

Node/Python 버전은 루트 README 기준. 루트에서 `npm run setup`, `npm run dev`.
신규 기본 화면은 `/`, 기존 비교 화면은 `/?view=legacy`다.
이미 5173/8000이 사용 중이라면 기존 프로세스를 종료하지 말고 별도 터미널에서:

```sh
# 루트 · 서버
uv run --directory backend uvicorn app.main:app --host 127.0.0.1 --port 8005
# 루트 · 별도 터미널의 화면
API_PROXY_TARGET=http://127.0.0.1:8005 npm --prefix frontend run dev -- --port 5175
```

화면 http://127.0.0.1:5175. 종료는 각 실행 터미널 Ctrl+C.
별도 API 키나 LLM 없이 동작한다. 지도 타일 표시와 최초 의존성 설치에는 인터넷 연결이 필요하고, Pretendard 폰트와 시연 이미지는 저장소에 포함돼 있다.

## 검증 시나리오

1. 첫 진입에서 12개 기본 마커, 추천 없음.
2. ‘보증금 천만 원, 월 80만 원, 강남역까지 40분’ → 임시 판정·입주일 질문.
3. 추천 집 클릭 → 비용/양방향 통근/판정·메인 토끼 기쁨 반응.
4. ‘월 50만 원은 꼭 지켜줘’ → 같은 선택 집 유지, 필수 위반·걱정 반응.
5. ‘가능하면 원룸’ 또는 ‘환승 없이’ → 선호/환승 조건 반영.
6. 관리비·경로 누락 집 선택 → null/미확인 이유 표시.
7. 새로고침 후 대화·조건·선택 집 복원. 새로 찾기로 초기화.
8. 서버 연결 실패 시 입력 보존·재연결, 이전 결과는 경고 표시.

## 캐릭터 말하기 연출

우사기 느낌의 ‘야하~’, ‘우라~’ 같은 짧은 감탄사를 인사·추천 반응에 섞는다.
예산/통근/미확인 이유는 존댓말 안내를 유지한다. 말풍선 꼬리·문자 순차 표시·말하는 동안의
작은 몸짓을 적용한다. 실제 음성·입 모양 동기화는 없다. 움직임 줄이기 설정이면 문장을 즉시 표시한다.

캐릭터는 상단 고정 영역 대신 대화창의 최신 답변 옆에서 말한다. 이전 답변은 작은 정지 얼굴,
선택 매물 반응은 최신 말풍선으로 표시하고 지도 선택 시 해당 위치로 스크롤한다.
상태별 임의의 흐음/앗 감탄사를 제거하고 사용자가 요청한 야하/우라 계열로 맞춘다.

## 시연 지도 탐색 개선

지도는 SVG로 건물 블록·골목·큰길·공원·한강·다리를 겹쳐 표현한다. 모든 구획과 위치는
설명용 도식이며 실제 지도/항공사진/역세권 자료가 아니다. 외부 지도·타일 API를 사용하지 않는다.
드래그/방향키 이동, 100~250% 확대·축소, 원위치 버튼을 제공한다.
매물과 직장 마커는 지도와 같은 변환 안에서 이동한다. 확대된 상태에서 집도 선택할 수 있다.

## 추천 기준 완화

필수 위반=비추, 필수 위반이 없고 정보 부족=판단 불가 정책은 유지한다.
판단 가능한 집은 입력한 선호의 절반 이상 충족하면 추천, 미만이면 쏘쏘다.
선호가 없으면 필수 충족으로 추천한다. 선호가 하나면 해당 하나를 충족해야 하므로 이전과 같다.
추천 이유에도 선호 충족 개수·맞는 항목·미충족 항목과 통근/환승/예산 초과량을 함께 표시한다.
변경 후 서버 테스트 142개, Ruff, 화면 lint/build 통과.

## 조건 요약과 표현 확장

대화창 위에 현재 확정된 필수·선호 조건, 직장·출근일, 미입력 정보를 표시한다.
칩을 누르면 기존 조건 편집기로 연결하고 바뀐 조건을 잠깐 강조한다.
지원 표현·금액/위치/날짜 확인 규칙은 docs/api.md 참고. 사용자 확인 전 모호한 후보는 지도에 반영하지 않는다.
브라우저에서 예산만 변경→취소, 단위 없는 예산→확인→적용→취소를 확인했다.
직전 변경 기록·확인 대기 조건은 브라우저 저장에 포함한다. 생성형 자연어 이해 기능은 아니다.

## 글자 크기 개선

프리텐다드 유지. 네이버 지도 웹 화면에서 확인한 입력 16px, 보조 링크 14px,
섹션 제목 19~24px 등의 위계를 참고하되 그대로 복제하지 않고 현재 화면에 맞췄다.
대화 본문 16px/1.7, 메시지 입력 16px, 상세 본문 14px, 조건/보조 정보 13px,
지도 마커 라벨 13px, 지도 주석 최소 12px, 상세 제목 24px, 월 지출 30px를 사용한다.
조건 칩·통근 정보는 긴 글자를 줄바꿈하며 지도 주석은 상세 패널 뒤에 표시한다.

사용자 화면 검토 후 상단의 ‘지금까지 알려주신 조건’ 요약 영역은 임시로 숨겼다.
조건 저장·대화 확인/취소·나의 조건 편집은 유지하며 요약의 새 위치는 후속 검토한다.

- 네이버 지도 웹 화면의 패널 여백(약 25px), 검색 본문 자간(-0.2px), 제목 자간(약 -0.7px)을 참고해 시연 화면에 맞게 조정했다. 데스크톱 패널 좌우 24px/모바일 20px, 요소 간 8·12·16·24px 간격을 사용한다. 대화 본문은 16px/행간 1.6, 상세 본문 1.6, 보조 문구 1.5로 정리했다. 지도 지명 특유의 자간은 유지한다.

- 지도 필터 위치에 대화로 확정한 조건을 가로로 표시한다(확인 전 해석 후보 제외). 필수/선호 구분과 조건 수정 연결을 제공한다. 상단 버튼을 ‘새로운 조건으로 찾아보기’로 바꾸고 기존 2단계 초기화 확인을 유지한다. 매물 상세 이름·닫기 버튼은 스크롤 중에도 상단 고정한다.

- 대화·지도 상단의 소개 제목 영역을 제거했다. 첫 대화 메시지가 안내를 맡고, 지도에는 조건 바와 매물/추천 개수 및 임시 결과 여부만 간결하게 표시한다.

- 대화창의 큰 캐릭터에 표정별 연속 동작을 적용했다. 추천은 가벼운 두 번의 점프, 쏘쏘/판단 불가는 좌우 갸웃, 비추는 느린 들썩임, 기본은 작은 바운스다. 기존 표정 전환·말하기 동작과 별도 레이어에서 이어진다. 지도/이전 메시지의 작은 얼굴은 정지 상태를 유지하고 OS 동작 줄이기 설정에서는 연속 동작을 끈다. 원본 아트 전체를 움직이는 방식이며 부위별 관절 애니메이션은 아니다.

- 월 출근 일수를 다른 조건과 함께 지도 위 조건 바에 배치했다. 미입력 조건도 표시하며 각 조건 버튼을 누르면 바로 아래에서 해당 값/필수·선호만 수정한다. 왼쪽의 중복 조건 영역은 제거했다.

- 데스크톱(1051px 이상) 대화창을 420px로 확대하고 큰 캐릭터는 150px로 유지해 추가 너비를 말풍선에 배분했다. 작은 화면에서는 기존 반응형 패널 폭을 유지한다.

- 지도 그림을 Leaflet 1.9.4 + OpenStreetMap 표준 거리 타일로 교체했다. API 키 없이 브라우저에서 보이는 범위만 요청하며 출처는 지도 왼쪽 아래에 표시한다. 네이버 지도 API/타일은 사용하지 않는다. 외부 네트워크가 필요하고 OSM 타일은 가용성을 보장하지 않는다. 오류 시 재시도 안내를 제공한다.
- 매물 좌표는 프런트 StreetMap.tsx의 동네 대표 지점이며 실제 매물 주소가 아니다. 기존 API의 x/y와 합성 통근 계산은 바꾸지 않았다. 집 선택 시 우측 상세 패널을 고려해 지도를 이동한다. 전체 보기/확대/축소/드래그/키보드를 지원한다.

- 네이버 부동산 필터의 간결한 버튼/펼침 화살표/선택 상태를 참고해 조건 바를 정리했다. 금액 표시는 만원 단위, 입력은 원 단위로 안내한다. 편집기는 지도 높이를 밀어내지 않는 버튼 아래 팝오버이며 바깥 클릭/닫기/Escape로 닫는다. 상세 패널이 열려 있으면 조건 영역과 팝오버가 가려지지 않도록 폭을 조정한다.

- 전체 바탕·헤더·대화/상세 패널·결과 영역을 크림색에서 흰색으로 통일했다. 캐릭터/이전 응답 말풍선은 중립적인 연회색으로 바꾸고 추천/선택/확인 상태 색은 유지한다.

- 지도 집 마커를 초록색 맵핀으로 교체했다. 추천 핀 안에만 승인된 토끼 얼굴을 넣고, 다른 상태는 초록색 핀으로 표시한다. 핀 끝을 동네 대표 좌표에 맞추고 선택한 핀은 외곽선으로 구분한다.

- ‘30분/사십 분/한 시간 안쪽이었으면(이였으면) 좋겠어’와 ‘월 예산 80만 원 안쪽’ 표현을 지원한다. ‘꼭’은 ‘좋겠어’보다 우선해 필수로 처리한다. ‘월세 60만 원’은 월세 단독 상한을 구현한 것으로 표시하지 않고, 관리비·통근비 포함 월 총예산으로 적용할지 먼저 확인한다. 금액이 없으면 원하는 금액을 질문한다.

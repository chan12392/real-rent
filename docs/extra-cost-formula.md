# 부대경비 계산식 — "진짜 월 거주비"

상태: **시안 / 팀 미합의 / API 연결됨(참고용)**. 구현은 `backend/app/engine/extra_costs.py`, 요율표는
`backend/app/engine/extra_cost_params.py`, 테스트는 `backend/tests/test_extra_costs.py`(92개)에 있다.
출처 조사: [공공](research/extra-costs-public.md) · [공공 외](research/extra-costs-private.md).

## 한눈에

```text
매물 + 생활 조건(인원·난방·입주월·거주 기간)
   │
   ├─ 매달 나가는 돈 ─────────────┐
   │   월세·관리비(실측 또는 추정)  │
   │   전기·가스(입주월부터 월별)   ├─▶ ① 현금 월 지출 (cash_monthly)
   │   수도·인터넷(관리비 포함이면 0)│
   │   통근비                       │
   │                               │
   ├─ 한 번 나가는 돈 ÷ 거주 개월 ──┤
   │   중개보수·이사·입주청소        ├─▶ ② 경제적 월 비용 (economic_monthly) = ① + 월할 + 기회비용
   ├─ 보이지 않는 돈                │
   │   보증금 × 연이율 ÷ 12  ───────┘
   │
   └─▶ ③ 입주 첫 달 필요 현금 = 보증금 + 첫 달 월세 + 중개보수 + 이사·청소
```

세 합계 모두 **범위(low~high)**와 **추정 비중(%)**을 함께 낸다. "얼마"와 "얼마나 믿을 만한지"를 같이 보여 준다.

## 재치 포인트 6가지

| # | 장치 | 왜 |
|---|---|---|
| 1 | **이중계상 방지** — 관리비 포함 항목(수도·인터넷 등)은 해당 공과금 0원 | 같은 돈을 두 번 세면 관리비 포함 매물이 불리해진다 |
| 2 | **입주월 기준 계절 반영** — 전기(하계 누진 구간 별도)·가스를 입주월부터 거주 기간만큼 월별 계산, 최고 달 표시 | 11월 입주자와 5월 입주자의 첫 겨울 부담이 다르다 |
| 3 | **일회성 비용 월할** — 중개보수·이사·청소 ÷ 거주 개월 | 6개월 살 집과 24개월 살 집의 중개보수 무게가 다르다 |
| 4 | **보증금 기회비용** — 보증금 × 연이율 ÷ 12 | "보증금 많고 월세 싼 집"과 반대 집을 같은 잣대로 비교 |
| 5 | **현금 vs 경제 비용 분리** | 매달 현금 흐름과 월할·기회비용을 나누어 참고 표시한다 |
| 6 | **근거 등급과 추정 비중** — 항목마다 실측/법정요율/공식단가/통계추정/가정 | 추정이 많은 합계는 숫자보다 범위를 보게 한다 |

"모름 ≠ 0" 원칙: 통근비를 모르면 합계를 **null**로 둔다. 관리비를 모르면 출처 있는 통계 추정치를 넣되
`estimated=True`와 추정 비중으로 드러내고, 기존 비교 판정(`unknown`)은 바꾸지 않는다.

## 항목별 식

| 항목 | 식 | 근거 등급 |
|---|---|---|
| 전기 | 누진(기타계절 0–200/201–400/400+, 하계 7–8월 0–300/301–450/450+) 기본요금 + 구간 단가, + kWh×(기후환경 9.0 + 연료비조정 5.0), 부가세 10%(반올림), 전력기금 2.7%(10원 미만 절사) | 요율: 공식 요금표 / 사용량: 가정 |
| 가스 | (기본 1,250 + MJ × 22.5268) × 1.1, 개별가스 난방일 때만 | 단가 **검증 필요** / 사용량: 가정 |
| 수도 | 인원 × 1일 L × 일수 ÷ 1000 ㎥ × (상수도 580 + 하수도 480 + 물이용부담금 170) + 기본요금 | 하수도 확인, 상수도 **검증 필요** |
| 중개보수 | 환산보증금 = 보증금 + 월세×100 (5천만 미만이면 ×70) → 구간 상한요율·한도, 주거용 오피스텔 0.4%, 부가세 0~10% 범위 | 법정요율 |
| 관리비 미확인 | 유형별 기준값(다방 대학가 원룸 평균 78,000원, 범위 59,000~105,000) | 통계추정(적용 범위 한정) |
| 기회비용 | 보증금 × 3.00% ÷ 12 (기준금리 2026-08, 대출이면 대출금리 입력) | 가정 |

## 숫자 예시 (합성 매물 L01)

입력: 보증금 1,000만 · 월세 50만 · 관리비 7만(수도·인터넷 포함) · 오피스텔 23㎡ · 1인 · 개별가스 · 11월 입주 12개월 · 통근 62,000원

| 구분 | 금액 |
|---|---|
| 월세 + 관리비 | 570,000 |
| 전기(12개월 평균, 최고 8월 37,267) | 26,129 |
| 가스(12개월 평균, 최고 1월 31,110) | 14,426 |
| 수도·인터넷 | 0 (관리비 포함) |
| 통근 | 62,000 |
| **① 현금 월 지출** | **672,555** (663,017~682,694, 추정 6%) |
| 중개보수 264,000 ÷ 12 | 22,000 |
| 이사 + 청소 240,000 ÷ 12 | 20,000 |
| 보증금 기회비용 | 25,000 |
| **② 경제적 월 비용** | **739,555** (719,683~761,361, 추정 12%) |
| **③ 입주 첫 달 필요 현금** | **11,004,000** |

검산(메인 손계산 일치): 전기 200kWh = 910 + 24,000 + 1,800 + 1,000 = 27,710 → 부가세 2,771 + 기금 740 = **31,221원**,
중개보수 = (1,000만 + 50만×100) × 0.4% × 1.1 = **264,000원**.
"월세 50만"이 실제로는 **월 67만~74만 원**짜리 집이라는 것이 이 계산식이 보여 주는 핵심이다.

## API 연결(참고용)

`POST /api/compare`의 각 `results[].living_cost`에 세 합계·항목·전기/가스 최고 월·관리비 추정 여부·요율 검증 상태를
반환한다. `living`은 선택이며 기본은 1인·개별가스·`move_in_by`의 월·경제적 월 비용 포함이다.
상세 계약은 [연결 규약](api.md#post-apicompare), 어댑터는 `backend/app/engine/living.py`,
연결 검증은 `backend/tests/test_living_api.py`에 있다.

**진짜 월 거주비는 참고용 시안이며 판정·순위에 쓰지 않는다.** 예산 판정은 기존 `cost.monthly_total_krw`
(월세+관리비+통근비)를 유지하며 기존 초기 현금·점수·추천도 바꾸지 않는다.
통근 미확인은 월 합계의 각 필드를 `null`로 유지하고, 관리비 덮어쓰기는 참고 계산에도 적용한다.

현재 합성 CSV·매물 모델에는 건물 유형·면적·이사 규모가 없다. 참고 계산에만 주거용 오피스텔(중개요율 적용요건 충족),
면적 미확인(면적 없는 관리비 추정표 사용), 소형 이사·청소를 가정하고 응답 `assumptions`에 표시한다.
위 L01 예시의 23㎡와 달리 API의 면적은 미확인이지만 L01은 관리비가 이미 입력되어 있어 세 예시 합계가 동일하다.
중앙·전기 난방의 별도 난방비는 기존 엔진에서 미확인이므로 계산에 포함하지 않는다.
요율의 `검증 필요` 상태는 API 연결만으로 확인 완료로 바뀌지 않는다.

## 남은 일

- `검증 필요` 값(상수도·가스 단가, 예금금리, 1인 사용량) 공식 원문 확인 후 params 갱신
- 팀 합의: 기회비용·일회성 월할을 비교 순위에 넣을지(현재 ①·② 모두 참고용이며 기존 월 지출로 예산 판정)
- 화면 표시와 실제 요율·사용량·건물 유형 등 적용 범위 검증

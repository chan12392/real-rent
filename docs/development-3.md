기준 자료는 `REALRENT_요구사항정의서_피드백반영.xlsx`의 `요구사항정의서` 시트다.

`feat/dev3-conversation`은 최신 main에서 시작해 `work/yunsoo` 시제품을 포함했다.
PR에는 기존 시제품 변경도 포함된다. 다른 팀원 리뷰와 병합은 아직 완료되지 않았다.

## 확정한 인터뷰 결정

- 화면: `work/yunsoo`의 대화·지도 화면을 사용한다.
- 모델/API 키: 아직 정해지지 않아 선정·연결을 보류한다.
- 자료: 분석 담당자의 확정본이 준비될 때까지 기존 합성 매물 12건으로 개발한다.
- 회사 위치: 강남역·서울역·여의도역 3곳으로 우선 시연하며 실제 주소 연결은 후속 작업으로 둔다.
- 추천 정책: 엑셀의 모든 상한 필수 방식 대신 현재 화면의 필수/선호 구분을 유지한다.
  필수 불일치는 제외하며 선호 절반 이상을 만족하면 후보로 남긴다. 추천 표시는 최대 3개다.
  미달 항목과 초과량을 설명하며 사용자 지시 없이 상한을 완화하지 않는다.

## 개발 3 담당 10개 기능

| 원본 셀 | 요구사항 | 완료를 확인할 동작 |
| --- | --- | --- |
| C5 | 회사 한 곳·입주일·보증금·월 지출·출근일·통근시간·환승·우선순위 입력 | 대화에서 8개 조건을 받으며 입력하지 않은 값은 미확인으로 유지한다. |
| C6 | 문장별 조건 추출, 출근일 검증 | 월 출근일은 0~31 정수만 허용하고 소수·범위 밖·모호한 표현은 질문한다. |
| C8 | 누락·모호한 조건만 질문 | 이미 받은 조건을 다시 요구하지 않는다. 모호한 회사 위치는 정확한 주소를 요청한다. |
| C10 | 확인 후 추천, 임의 기본값 금지 | 모든 필수 조건을 사용자가 확인하기 전에는 추천·경로 조회를 시작하지 않는다. |
| C27 | 해당 매물 문서 검색(RAG) | 매물 ID로 검색 범위를 제한하며 다른 집의 관리비·조건을 가져오지 않는다. |
| C28 | 계산값에 따른 설명, 문서명·근거 문장 | 금액·순서는 계산 함수 결과를 사용한다. 문서명과 실제 근거 문장을 함께 반환하고 근거 없으면 확인 불가로 답한다. |
| C29 | 변경된 조건만 반영 | 월 예산만 바꾸면 회사·입주일 등 다른 조건은 유지한다. |
| C30 | 변경 확인 후 재계산 | 변경 뒤 다시 확인을 받고 필터·비용·정렬을 실행한다. 이전 확인 상태로 새 조건을 실행하지 않는다. |
| C32 | 후보 없음의 이유 구분 | 조건 불일치, 경로 조회 실패, 자료 미확인을 구분한다. 복수 원인도 누락하지 않는다. |
| C33 | 바꿀 조건은 사용자가 선택 | 어떤 조건을 변경할지 묻고 사용자의 선택 전 예산·통근 상한을 완화하지 않는다. |

공통 원칙 C44는 LangGraph로 질문 → 조건 확인 → 집/경로 조회 → 계산 → 설명을 연결하는 것이다.
RAG는 설명의 근거를 찾고, 필터·금액·정렬은 기존 코드가 담당한다.

## 구현과 남은 빈틈

| 항목 | 구현한 동작 | 남은 작업·제한 |
| --- | --- | --- |
| 조건 수집·검증 | 8개 조건, 출근일 0~31 정수, 비용/시간 우선, 누락·모호한 값 질문 | 규칙 기반 추출. 임의의 자연어를 이해하는 실제 모델은 미연결 |
| 확인·변경 | 전체 조건 확인 후 계산, 변경 시 확인 해제, 다른 조건 유지 | 새로고침은 현재 브라우저 저장 범위. 서버 계정·대화 저장 없음 |
| 회사 위치 | 강남역·서울역·여의도역, 다중 회사·지원 밖 주소는 재질문 | 임의 주소의 지오코딩·주소 후보 선택 미연결 |
| 비용·추천 | 기존 탐색 판정 재사용, 필수/선호 유지, 월 지출/왕복 통근 우선 정렬, 최대 3개 강조 | 주거 유형·명시적 조건 해제는 기존 화면 정책 유지 |
| 설명·문서 검색 | 계산값 설명, 매물 ID별 문서 원문·제목 인용, 근거 없으면 확인 불가 | 로컬 JSON 검색. LLM·임베딩 기반 RAG 및 분석 확정 문서 미연결 |
| 후보 없음 | 필수 미달/조회 실패/경로·관리비 미확인을 구분하고 수정 조건 질문 | 실제 제공자 실패 대신 합성 입력으로 실패 계약 검증 |
| 화면 연결 | 확인 카드·우선순위 편집·최대 3개 지도 표시·문서 근거 표시 | 최종 분석 자료로의 시연은 후속 확인 필요 |

기존 `/api/compare`는 변경하지 않는다. 필수/선호에 관한 위 결정은 엑셀과 다른 합의 사항이다.

## 다음 연결에 필요한 입력

| 대상 | 확인할 내용 | 현재 상태 |

| 대표님 | AI 모델 이름, 키 준비 여부, 외부 API 비용·사용 제약 | 선정·연결 보류. 키 값은 대화나 저장소에 기록하지 않음 |
| 분석 | 확정 매물 12건, ID가 일치하는 문서 ID·제목·원문·출처·기준일 | 준비 중. 현재 data/references/explore.json은 합성 자료에서 파생한 임시 문서 |
| 개발 2 | 주소 확정 결과, 양방향 경로·실패 코드, 조회 시점·시연 여부 | 실패 코드는 docs/api.md에 명시. 실제 제공자 어댑터와 주소 확정 계약은 후속 연결 |

월 출근일 0일에도 시간·환승 조건을 적용하는 기존 정책을 유지한다.
단위 없는 금액·상대 날짜는 해석한 값을 먼저 확인하고 전체 조건도 다시 확인한다.
금액은 원 단위 정수로 검증하며 소수 원을 임의로 반올림하지 않는다.
모델을 연결하더라도 서버의 형식·범위·확인 대상 검증과 계산 함수를 유지해야 한다.

## 연결 경계와 검증

LangGraph 흐름은 extract → respond → (확인된 경우) compare → explain이다.
확인 전에는 매물 위치·기본 정보만 표시하고 계산·추천·문서 검색은 실행하지 않는다.
문서 누락·파손 시 계산 결과를 보존한다. 새 규약과 요청 예시는 [api.md](api.md)를 따른다.

구현 경로는 `backend/app/engine/`, `app/api/explore.py`, `app/schemas/explore.py`,
`app/domain/explore.py`, `frontend/src/features/explore/`, `data/references/explore.json`이다.
기존 LangGraph 의존성을 사용하며 새 모델 SDK·벡터 DB·환경 변수는 추가하지 않았다.
외부 주소·교통 호출과 캐시는 개발 2, 비용 계산·필터·정렬은 저장소의 `app/domain/` 경계를 유지한다.
엑셀 C15의 편도별 경로 응답 정리 담당은 개발 2이므로, 개발 3은 전달받은 결과를 소비한다.

검증 사례는 입력 누락·모호함, 출근일 0/31/32/소수, 확인 전 조회 금지, 예산만 변경,
회사 변경, 비용/시간 우선, 조건 미달/경로 실패 혼합, 다른 매물 문서 혼입 방지,
근거 없음·파일 파손, 잘못된 매물 파일, 선택 집 유지와 새로고침 복원을 포함한다.
합성 입력의 통과를 실제 모델·교통 API 검증으로 표시하지 않는다.
서버 변경 후 `uv run ruff check app tests`, `uv run python -m pytest`를 실행하고,
화면 변경이 있을 때 `npm run lint`, `npm run build`도 수행한다.
